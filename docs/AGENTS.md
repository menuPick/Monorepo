# AGENTS.md

> 기준일: 2026-11-02

## 현재 작업 모드

현재는 기준선 보존 모드입니다. 사용자가 명시적으로 요청하기 전에는 큰 코드 변경을 시작하지 않습니다.

보류 대상:

- Java 서버의 Go 전환
- Python AI 서버 추가
- AI 추천·위험 메뉴 판별 구현
- 일일 퀘스트 구현
- 데이터베이스 교체
- API 계약 변경

## 작업 전 확인

1. `docs/README.md`와 이 파일을 읽습니다.
2. 관련된 최신 `docs/records/YYYY-MM-DD.md`가 있으면 읽습니다.
3. `git status --short`로 기존 변경사항을 확인합니다.
4. 요청 범위를 벗어난 리팩터링이나 성능 개선을 하지 않습니다.
5. 생성 파일, `build/`, `.dart_tool/`, `data/`를 직접 수정하지 않습니다.

## 보존해야 할 기준

- 사용자 앱 엔트리포인트는 `lib/main.dart`입니다.
- 관리자 앱 엔트리포인트는 `lib/admin_main.dart`입니다.
- 사용자 Web 첫 진입에 관리자 코드를 포함하지 않습니다.
- Flutter가 사용하는 기존 API 경로와 JSON 필드명을 임의로 바꾸지 않습니다.
- 개인 로컬 데이터는 `data/`에 저장하며 Git에 추가하지 않습니다.
- 환경별 API 주소는 `API_BASE_URL`로 주입합니다.
- 서버의 정상 로그에는 필요한 상태만 남기고 요청 본문·토큰·비밀번호를 출력하지 않습니다.

## 코드 변경이 필요한 경우

코드 변경 전에 다음 내용을 사용자에게 먼저 알립니다.

- 변경하려는 파일
- 변경 이유
- 기존 동작에 미치는 영향
- 검증 방법

사용자가 범위를 승인한 뒤에만 수정합니다. 단순 문서 정리는 코드 변경으로 간주하지 않습니다.

## 미래 기능을 다룰 때

- AI가 메뉴를 직접 삭제·공개·차단하지 않도록 합니다.
- AI 결과는 점수와 근거로 저장하고 최종 변경은 규칙 또는 관리자 승인을 거칩니다.
- AI 작업과 퀘스트 보상은 중복 처리와 재시작 상황을 고려합니다.
- Go, Python, Redis, PostgreSQL 같은 기술을 먼저 추가하지 말고 설계와 필요성을 먼저 확정합니다.

## 검증 원칙

코드 변경이 승인된 경우에만 관련 검증을 실행합니다.

- `cd server && mvn -q test`
- `cd .. && flutter analyze`
- `git diff --check`

완료 보고에는 변경 파일, 검증 결과, 남은 제약을 적습니다.

## 날짜별 기록 규칙

작업이 끝나면 `docs/records/YYYY-MM-DD.md`에 중요한 내용만 기록합니다. 파일이 없으면 새로 만듭니다.

기록 형식:

```md
# YYYY-MM-DD 작업 기록

## 결정
- 앞으로 유지할 중요한 결정

## 변경
- 실제로 변경한 핵심 파일과 동작

## 검증
- 실행한 명령과 결과

## 보류
- 다음 작업으로 넘긴 내용과 이유
```

기록하지 않는 내용:

- 단순 파일 탐색과 반복 명령
- 중요하지 않은 터미널 출력
- 이미 README나 AGENTS에 적힌 일반 규칙의 반복
- 사용자의 개인정보, 토큰, 비밀번호, 전체 로그

기록은 Roadmap의 진행 근거가 되는 결정·변경·검증·보류만 남기는 간결한 일지로 관리합니다.
